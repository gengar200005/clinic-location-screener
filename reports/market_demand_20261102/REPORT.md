# 시장 수요·의료소비 연결 시범 결과

검증일: 2026-11-02. 작업 브랜치: `feat/market-demand-pilot-20261102`.

## 1. 구현 결과와 의사결정에 주는 도움

기존 앱에 **시장 수요·의료소비** 영역과 6곳 통합 비교 화면을 추가했다. 후보 선택, 1km/1.5km 주거 수요·공급 비교, 행정동 일반의원 금액/건수/건당 금액/점포 변화, 연령별 금액, 상권 소비활동, 직장인구, 길단위인구 주변합, 건물 확인 상태, 기존 판단→새 근거→다음 행동을 함께 표시한다. 의료금액 그래프와 22분기 상세표를 제공한다. 기존 지도에는 동일 행정동의 시장 문맥 요약과 정확한 시범 조사점 상세 링크를 붙였다. 두 좌표의 배후 수요를 섞지 않는다.

단순히 경쟁기관이 적은 곳을 찾는 대신, **시장 결제 활동이 어느 방향으로 변하는지와 기존 기관의 실제 검사 수용 여력·가용 공간을 나누어 조사**할 수 있다. 다만 현재 자료로 신규 의원이 확보할 환자 수나 몫은 알 수 없다. 시장 성장과 신규 진입 기회는 별개다.

공식 순위 교체, 신규 가중치/성공점수/환자 수/점유율 예측은 하지 않았다. 주거·직장·생활인구 합산, 점포당 평균 의원 매출, 행정동 금액의 건물·반경 배분도 하지 않았다.

전체 요구를 완료한 상태는 아니다. **250m 반경 인구 및 최근 4주 평일/주말/공휴일 비교는 미완료**다. 경기 검증 매출의 통합 척도 비교도 하지 않았다. 미확보를 0점으로 처리하지 않았다.

## 2. 최신 상태와 보존

- 원격 main은 실제 조회·fetch 결과 `8ec22be`(PR #7 병합). 로컬 HEAD `6545c75`와 원격 main의 파일 내용 차이는 없다. 커밋 이력의 병합 커밋 유무와 내용 차이를 구분했다.
- 원본 `../clinic-location-screener`와 별도 PR 작업 폴더의 기존 미커밋·로컬 전용 원자료를 보존했다. 활성 작업 폴더에 새 기능 브랜치를 만들었으며 자동 pull/reset/clean은 하지 않았다.
- 기존 v7/v3 점수 계산, 원본 JSON, 매출 처리 기능, 지도 hover 색상 방식을 교체하지 않았다. `preservation_before.json`과 `preservation_after.json`에서 보호 대상 33개 파일 SHA256이 일치한다. 보호 범위는 기존 scored parquet와 research/revenue/boundaries JSON이다. 기존 v3 화면과 분석 파일은 수정하지 않았다.
- 키 출력·저장·커밋 없이 공식 CSV 파일 방식으로 진행했다. 커밋/푸시/병합/배포하지 않았다.

## 5. 발견한 문제와 안전하게 보류한 계산

1. **소비 갱신 주기 충돌:** 공식 설명은 Q4 연1회 갱신·이후 Q1~Q3 반복이나, 6개 동의 2026Q2 소비 값이 2025Q4 값과 다르다. 상도1동은 각각 8,506,938,000과 8,188,328,000이다. 주기 설명과 실측 시점을 확정할 수 없어 성장률을 생성하지 않았다. 삭제된 월평균 소득을 복원하지 않았다.
2. **직장인구 반복:** 6개 동 모두 해당 Q4 값과 최신 표시 값이 같다. 동일하다는 사실만으로 실제 갱신·관측일을 확정하지 않았다. 분기 성장률을 계산하지 않았다. 상도3,543명·구로10,594명·우장산3,048명·중앙1,301명·화곡8동1,853명·증산1,939명은 주거인구와 더하지 않았다.
3. **250m 다중 행정동 행:** 날짜/시각/행정동/격자는 고유하지만 격자/시각은 고유하지 않다. 공식 정의 XLSX·22쪽 매뉴얼·샘플을 확인했으나 분할 행인지 다른 추정인지 합산 의미를 확정할 설명을 확보하지 못했다. 합산/대표값/면적배분 모두 적용하지 않았다. 비공개(*) 162,031개와 관측값353,444개는 6개 반경 합집합에서 검사한 셀 수이며 비공개를0으로 바꾸지 않았다.
4. **격자 미연결:** 하루 원자료의 8,567개 격자 ID 중1개가 공식 선택기 중심점과 미연결이다. 후보별 중심점 포함 격자 수와 관측 격자 수를 따로 표시한다. 미연결은0명이 아니다. 1km/1.5km는 직선반경이며 셀 일부 교차는 중심점 포함 근사, 보행 진료권이 아니다.
5. **4주 미수행:** 하루 검증의 합산 의미가 해결되지 않아 추가28일을 다운로드하지 않았다. 평일/토요일/일요일/공휴일별 관측일수·진료시간대 평균·연령×시간별 평균을 완료로 표시하지 않았다. 시간별 숫자를 더해 고유 방문자로 만들지 않았다. 행정동 길단위인구에는 없는 연령×시간 교차값을 생성하지 않았다. ‘60세 이상’을 다른 나이 구간으로 바꾸지 않았다.
6. **시기 불일치:** 의료·상권 최신 표시2026Q2와 생활인구2026-10-29는 나란히 제시하지만 동시기 상관관계·전환율을 계산하지 않았다. 실제 경쟁기관 인력/장비도 과거 신고 스냅샷이며 현재 검사 수용 능력이 아니다.
7. **추가 검증 시도:** 공식 행정동 생활인구 OA-23016의 하루 필터로 대조를 시도했으나 서버가 필터를 적용하지 않아 약195MB·645,624행 응답을 반환했다. 하루 데이터로 오인해 저장·사용하지 않았고 반복 호출하지 않았다. 이 응답을 검증된 대조 자료나 4주 자료로 계산에 넣지 않았다.

## 6. 검증 결과

- 관련 Python 검사38개 통과. 새 검사8개는 고정 인메모리/임시ZIP 자료로 결측/0/*/NaN/무한대/음수, 소수 문자열 보존, 분모0, 정확한 전년 동기, 업종/코드/중복, 코드-동명/금액 불일치, 연1회 반복값, 없는 교차값 방지, 다중 행정동 격자 합산 차단을 검증한다. API를 호출하지 않는다.
- 실행 가능한 전체 Python 검사94개 통과, 기존 경고2개(pandas 결합·빈 평균). 로그 `pytest_available.txt`.
- 전체 수집은 기존 모듈3개에서 미설치 의존성으로 실패: `test_hira_guard.py`(tenacity), `test_pop_weighted_centroid.py`와 `test_web_export_v7.py`(geopandas). 해당 기존 코드와 환경은 변경하지 않았다. 전체 통과로 표시하지 않는다. 로그 `full_collection.txt`.
- Node 검사7개 통과(기존 지도3 + 신규4), JS 구문 검사와 CRLF-aware diff 공백 검사 통과.
- 실제 브라우저에서 6개 후보 선택·그래프·비교6행, 1km→1.5km 주거 수요 변화/행정동 매출 불변, 기존 의원 반경1km→1.5km, 매출 기준분기 변경, 전체 후보 검색→구로2동 연결, 지도 타일/벡터 유지, 콘솔 오류 없음 확인.
- 새 화면 데스크톱1280×900, 모바일390×844에서 루트 가로 넘침 없음 확인. 모바일 표는 의도한 내부 가로 스크롤이며 후보 변경 가능. 미리보기 `desktop.jpg`, `mobile.jpg`, `preview.jpg`. 화면에 없는 데이터의 검증을 UI 테스트로 대체하지 않았다.
- 보호 대상33개 SHA256 일치, 기존 공식 점수·JSON 불변. `preservation_after.json`.

`fetch_market_context --acquire-missing`만 명시적으로 켜면 없는3종 공식 CSV를 확보한다. 기존 원자료는 덮어쓰지 않는다. 한 자료의 확보 실패는 다른 자료 확보를 중단하지 않으며, 원자료 미확보는 미연결 상태로 표시한다. 생활인구·공식 경계 캐시는 현재 로컬 자료를 사용한다. 하루 파일 원본 양식은 OA-22784 공식 페이지의 2026-10-29 다운로드 항목(`infId=OA-22784, infSeq=1, seq=261029`)이며 무차별 기간 수집 스크립트를 추가하지 않았다.

웹 서버가 없다면 `python -B -m http.server 8770 --bind 127.0.0.1 --directory web`로 띄워 `http://127.0.0.1:8770/market-demand.html?v=2`를 연다. 기존 앱 상단의 시장 수요·의료소비 링크도 연결된다. 기존 로컬 서버 루트가 다른 폴더라면 URL만 같아도 새 결과가 아닐 수 있으므로 작업 폴더를 확인한다.
