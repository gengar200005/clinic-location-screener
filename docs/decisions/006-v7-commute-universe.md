# ADR-006: v7 후보 범위 — 출퇴근 60분 필터 + 경부축 제외 + 50~69세

**날짜**: 2026-10-12
**상태**: 채택 (feature/v7 브랜치)

## 배경

v6까지 후보 범위는 서울 25구 + 경기 9시 시군구 화이트리스트(652동)였고, 통근(T)은 점수의 10%였다.
v7에서 사용자 결정:

1. 이촌동 기준 **대중교통 또는 출근시간 자차 1시간 이내**면 모두 후보.
2. **경기 경부축·동남권 전체 제외** — "현실적이지 않음". 과천 포함.
3. **출근·퇴근 모두** 판정에 포함.
4. **통근은 점수에서 제외** — 필터로만 사용.
5. 인구 타깃 **40+ → 50~69세** (가온내과 50~70대 위·대장 내시경 검진).

## 결정

### 후보 범위 (`config/target_regions.yaml`, `config/regions.py`)

```
context_sido = 서울 · 경기 · 인천            ← 의원 공간조인·반경 경쟁 카운트
사전 후보   = context − exclude_sgg − 이촌 직선 55km 밖
최종 후보   = 사전 후보 ∩ 통근 OK
```

- exclude_sgg(경기): 성남·하남·과천·용인·광주·수원·화성·오산·의왕·군포·안양·평택·안성·이천·여주·양평.
  평택·안성은 사용자가 명시하진 않았으나 경부축 남단이라 함께 제외 (과천 질의 시 범위 확인).
- 의원은 **context 전체**에 조인 — 제외 지역 의원도 경계 인근 후보의 반경 경쟁에 반영.
  (v6은 대상 동 폴리곤에만 조인 → 화이트리스트 경계 밖 의원이 반경 카운트에서 누락)

### 통근 판정 (`scrapers/commute_isochrone.py`, `scoring/commute.py`)

| 구간 | API | 방향 | 시각 |
|---|---|---|---|
| car_am | Kakao `v1/future/directions` | 이촌 → 동 | 화 07:30 |
| car_pm | Kakao `v1/future/directions` | 동 → 이촌 | 화 18:30 |
| transit_am | ODSay | 이촌 → 동 | (시간대 없음) |
| transit_pm | ODSay | 동 → 이촌 | (시간대 없음) |

```
자차 OK      = max(car_am, car_pm) ≤ 60
대중교통 OK  = max(transit_am, transit_pm) ≤ 60
후보         = 자차 OK or 대중교통 OK
```

구간 결측(경로 없음·오류)은 통과로 보지 않는다. 어느 수단도 OK가 아니고 결측이 있으면
`commute_status=unknown`으로 `data/scored/excluded_commute_*.parquet`에 기록.

### 가중치

`W_COMMUTE = 0`, C·P 0.5/0.5 (3단계 신규 지표 추가 시 재조정). t_* 컬럼은 표시용으로 유지.

## 발견된 v6 결함

`scrapers/kakao_car.py`는 `v1/directions`(실시간)에 `departure_time`을 넘겼으나 반영되지 않는 것으로 보임.
2026-10-12 같은 구간 비교:

| 목적지 | future 07:30 | 실시간(호출 시점) |
|---|---|---|
| 운정중앙역 | 38분 | 69분 |
| 킨텍스 | 28분 | 62분 |
| 동탄역 | 58분 | 60분 |

→ v6 T값은 "평일 07:30"이 아니라 **스크래핑 시점 교통**이었을 가능성이 높다.

## GTX-A

ODSay에 반영 확인. 서울역↔운정중앙·킨텍스, 수서↔동탄 구간만 경로에 등장하고 서울역↔수서 연결은 없음
(삼성역 미개통과 일치). 이촌→운정중앙 42~45분(4호선+GTX), 이촌→동탄역 75분(수서 경유).
개원 시점(2027-05) 개통 변화는 추정치로 넣지 않는다.

## 영향

- 백분위 정규화의 모집단이 바뀌므로 **v6과 점수·순위 직접 비교 불가**.
- 동 단위 결과(통근 4구간)는 캐시 `data/cache/commute_v7.parquet`에 영구 보관.
- Notion DB 속성명("40+인구")은 5단계에서 변경 — 현재 값만 50~69세.
