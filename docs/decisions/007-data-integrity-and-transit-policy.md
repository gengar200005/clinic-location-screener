# ADR-007: 데이터 무결성 가드 + 대중교통 수동 확인 정책

**날짜**: 2026-10-20
**상태**: 채택 (main, PR #2·#4)

## 배경

1. **10/17 주간 cron 사고.** HIRA 병원정보서비스가 서울 4,000/4,765, 경기 0, 인천 0을 **오류 없는 정상 형식**으로 반환했다. 수집기는 이를 성공으로 처리했고, 부분 데이터로 점수가 계산되어 대시보드와 Notion을 덮어썼다. Top30 30곳 중 16곳이 바뀌었다(수색동 21 → 79위). 원인(점검·일시 장애·순간 제한)은 불명이며, 같은 요청을 10/20에 재실행하자 정상이었다.
2. **v7 입력은 로컬 raw 파일.** 장비 CSV는 data.go.kr에 로그인해야 받을 수 있어 runner에 없다. 그 결과 검진기관·추세·생존율 입력이 빠지면 파이프라인이 경고만 남기고 해당 지표를 건너뛴 점수를 만들 수 있었다.
3. **ODSay 약관 (2026-10-13 사용자 확인).** 대중교통 API는 "서비스용 단일 호출" 용도로 한정된다. 분석·연구 목적이나 대량 호출은 사전 협의가 필수이며(분석용 데이터 구매 2,000만원 이상), 협의 없이 쓰면 예고 없이 이용이 제한될 수 있다. Basic 무료는 하루 30건이다.

## 결정

### 1. 입력 이상 시 갱신 skip — 덮어쓰지 않는다
- `scrapers/hira_clinic.py`: totalCount=0이나 빈 페이지가 오면 재시도한다(`IncompleteResponse`, tenacity 4회). 시도별 수집량이 totalCount보다 적으면 저장하지 않고 실패한다.
- `scoring.pipeline --strict` (GH Actions): 아래 경우 실패한다.
  - 추세(`kosis_pop_age_at_*`)·검진기관·인허가 입력 누락
  - GI 장비 플래그 전부 False
  - 시도별 의원 수 < `MIN_CLINICS_PER_SIDO`(500)
- 실패하면 web_export·commit-back·Notion 단계가 실행되지 않는다. 대시보드·Notion에는 **직전 정상 결과가 유지**되고, Actions가 실패 알림을 보낸다.
- commit-back은 Notion 단계보다 앞에 둔다. Notion만 실패해도 대시보드·캐시는 저장된다.
- 장비 데이터는 runner 캐시로 커밋한다: `data/cache/clinic_equipment.parquet`, `data/cache/egd_keys.parquet`. 장비 CSV를 연 1회 갱신할 때 로컬에서 `python -m scrapers.hira_equipment`를 실행한 뒤 커밋한다.

### 2. 대중교통은 자동 대량 수집 금지 — 수동 확인
- `scrapers.commute_isochrone`의 기본 구간은 자차(`car_am`, `car_pm`)만이다. 대중교통 구간은 `--legs`로 명시할 때만 호출한다(약관상 권장하지 않음).
- 자차로 60분을 넘고 대중교통이 미확인인 동은 `commute_status=exceed_car`로 후보에서 제외한다.
- 사용자는 카카오맵으로 확인한 시간을 `data/manual/transit_manual.csv`(`transit_am_min`, `transit_pm_min`)에 입력한다. 입력값은 다음 실행에서 반영된다.

## 대안

- 부분 데이터라도 갱신 + 경고만 표시 — 기각. 잘못된 순위가 답사 의사결정에 바로 쓰인다.
- 직전 결과와 비교해 변동이 크면 차단 — 보류. 실제 시장 변화와 구분하기 어렵다. 우선 절대 하한(시도별 500)만 둔다.
- ODSay 유료(Standard, 건당 25원) — 분석 용도는 별도 협의 대상이라 기각.
- 서울시 대중교통 환승경로 공공 API — 경기·인천 커버리지를 확인하지 못해 보류.

## 영향

- 데이터 이상이 있는 주는 갱신이 한 주 늦어진다(정확성 우선).
- 대중교통으로만 60분 안에 드는 동은 수동 확인 전까지 후보에서 빠진다. 다만 자차로 60분을 넘는 동은 대부분 61~65분 경계에 있다.
